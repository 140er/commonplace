### The account table check reviews the grant scope digest columns as plain

`runner_machines.grant_scope_sha256` and `runner_machines.binding_scope_sha256` hold the SHA-256 of a validated grant scope record: provider instance id, runtime mode, workspace strategies, project ids and MCP server names, serialized canonically and capped in size. The digest is a content fingerprint used to notice a changed scope and reset an owner's confirmation; it carries no credential and cannot be turned back into one. The credential-like column check in `tests/test_commonplace_account_tables.py` flagged both names on their `sha` part, so they are now listed as reviewed plain columns, next to the other content digests, instead of being redacted from the account export. The check itself is unchanged and still fails for any new credential-like column that is neither redacted nor reviewed.
