### Card panel load

- The Deck card panel took 3 to 12 seconds to leave "Loading card…" for two reasons that added up. The shell asked for the card only after the project refresh had finished (project list, needs-me, roster, board cards, chat), so the card read sat at the end of a serial chain. And the card read took the board's write lock like a write, so any board write in flight held it too. While it loaded the panel was a plain grid column, so the board squeezed to one word per line; only a drawn card became an overlay.
- Decision: the panel is the drawer from the first moment (preview with the known fields), the card read starts when the card is opened and runs beside the refresh, and `task_show` reads on a read-only snapshot unless something is due to expire or wake, in which case it takes the write path as before. A write-locked read is kept only where it can change state. The board columns also keep a 220 px minimum whatever the panel holds, so a panel in any state scrolls the board instead of squeezing it.
- Rejected: caching card reads in the browser (a stale card with live buttons) and making every read route lock-free (several read routes expire claims or wake snoozes, which are writes).
