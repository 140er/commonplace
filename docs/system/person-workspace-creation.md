### Person-only workspace creation and abuse controls

`POST /api/workspaces` provisions an additional workspace for the signed-in person. This route already existed on the implementation base; this change adds stricter authority and resource controls and opens the new workspace's Home after confirmation. The instance administrator's existing workspace inventory automatically includes its control row.

The request is an application/json object containing exactly `name`, `request_id` (a UUID) and `csrf`. The caller must send the `cmmn_session` cookie, an explicit same-origin Origin and the session-bound `csrf` value returned by `GET /api/workspaces`. No bearer authority, connection, OAuth grant, PAT, pipeline-feed token or MCP scope can create workspaces. An account marked `users.is_person=0` is refused even with a session. Existing accounts migrate as persons because the preceding schema had no service-account classification; new service accounts must use `is_person=False` at creation.

A successful fresh request returns 201 with `{"workspace":{"id":"ws_<opaque>","name":"Example","slug":"example-<opaque>","role":"owner"}}`. A replay of the same person's request and name returns 200 with the same object; reusing that request for another name returns 409. Creation does not itself rotate the session: the UI then calls `POST /api/workspaces/switch` and forces a reload at `/app/#/`, the workspace Home (Classic resolves its default landing to Bots). If switching fails, the result offers Open workspace to retry switching without provisioning again.

Names use the shared `sanitize_name` validation: trimmed, 1–128 characters, alphanumeric endpoints, letters/digits and internal spaces, underscores, periods, apostrophes or hyphens; path separators, traversal, control characters and markup are refused. Invalid names/fields/request ids return 400 with a plain error. Slugs derive from the name with a unique generated id suffix; directories are keyed by the opaque workspace id, never by submitted text. Signup, CLI and this route use `ControlDB.create_workspace`; browser creation retains `assign_signup_plan` and shares signup's empty default Commonplace board initializer. Rules and memory follow their ordinary fresh-workspace initialization, with no copied rules, cards, memory or memberships. A pending initialization marker makes the default-board step retryable across the two databases.

`COMMONPLACE_WORKSPACE_LIMIT` defaults to 5 owned workspaces per person, including CLI-created ownership and excluding ordinary memberships. `COMMONPLACE_WORKSPACE_CREATIONS_PER_HOUR` defaults to 3 successful creations per person per rolling hour. `COMMONPLACE_WORKSPACE_CREATIONS_PER_DAY` defaults to 20 successful creations per instance per rolling 24 hours. Each override is a positive integer; invalid configuration refuses creation with a plain validation error. The shared token-bucket helper charges both rate policies together, and the durable `workspace_creations` ledger also enforces the rolling limits across restarts and concurrent gateways. Replays spend no extra allowance. With `COMMONPLACE_PLANS=on`, the existing plan module separately counts owned workspaces: the free allowance is 5 and existing paid plans are preserved. This introduces no billing service or payment flow.

Unsigned requests return 401. Wrong authority, csrf, signup closure, owned cap or plan limit returns 403. Rate refusal returns 429 with Retry-After. Backup pause, the admission freeze or an exclusive maintenance fence returns 503 with Retry-After 30. The existing storage_guard helper checks the data volume with `MEMPALACE_MIN_FREE_BYTES` (gateway default 256 MiB; 0 explicitly disables the floor); `disk_low` returns the existing 507 storage_full refusal with Retry-After 30. These checks precede provisioning. Audit events record who, when, workspace id and decision, without the submitted name or content. The instance inventory remains the administrator's view; ordinary workspace lists expose only memberships.

Deleting workspaces, ownership transfer, joining another person's workspace, billing and a workspace-creation MCP tool are deliberately outside this endpoint. The UI's confirmation names the isolated result; success switches in both Deck and Classic, on desktop and phone. A failed switch can be retried from the created result; a failed create displays its plain reason.
