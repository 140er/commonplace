### Workspace-name validation before confirmation

The workspace switcher's name step uses the authoritative `sanitize_name` rules from `mempalace/config.py`, returned as `name_rules` by `GET /api/workspaces`. This is an additive description for the form. `POST /api/workspaces` keeps the existing request fields, authority, response shape, statuses and server error strings. The server's accepted set is unchanged.

The source remains the server's compiled name pattern and maximum length, with the sanitizer's path and null exclusions. For the browser description, the server expands its Unicode letter/digit and whitespace classes into portable character ranges once and caches them. The client consumes that pattern in Unicode mode, the server's trim pattern, maximum codepoint count and forbidden tokens. JavaScript's native word classes, trim and UTF-16 string length do not silently change Python's rules. A drift test compares browser acceptance and normalization with the actual sanitizer.

Names have 1–128 letters or digits, may contain internal spaces, underscores (_), periods (.), apostrophes (') and hyphens (-), and must begin and end with a letter or digit. Path separators, consecutive periods (..), nulls and characters outside that set remain refused. `UX-TEST leave`, `My team` and `A team's space` pass. `UX-TEST (leave)`, `[Research]` and `bad/..<script>x</script>` fail. Parentheses and brackets are deliberately not added to the server's set.

Before this change, the last example left Continue enabled, reached confirmation and only then produced `Workspace name contains invalid path characters` after a create request. Now both Deck and Classic keep Continue disabled and show this inline string: `Names cannot contain /, \, or consecutive periods (..). Use 1–128 letters or digits, with internal spaces, underscores (_), periods (.), apostrophes (') or hyphens (-). Start and end with a letter or digit.` Other disallowed characters name the character problem and list the same allowed set. Overlength input retains `Use 128 characters or fewer.`

The form checks on input and again on submit, before entering confirmation. Missing rules keep creation unavailable until the switcher is reopened. Even after client acceptance, the server still validates the submitted name and its plain refusal stays visible. No workspace is created merely by typing or by advancing to confirmation. Both looks use the same validation controller, with browser coverage at 1280 and 390 pixels.
