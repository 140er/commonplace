### Browser cases follow the Deck default

The optional real-browser cases were written against the classic look and the first Deck tokens, so once the Deck became the default and took the Capy tokens many of them failed on a plain checkout while no quick check ran them. They now assert what each look really renders: the Deck surface, well, ground, ink and line tokens, the Deck Memory search label and its collapsed "More filters", the consent checkbox before a Deck import, the rail or top-bar workspace button (the Deck palette lists destinations only), the 16px inset of the Needs me surface and the shell root class. Cases about the classic look open `/app/?ui=classic`.

No product code changed. Where the Deck differs from the design a case encoded (Needs me segment style, import actions clearance on a short phone) the assertion stays behind a strict expected failure (one case) or a looser bound with a comment (one); the Compute bundle badge gap was closed afterwards, see "Deck link count badge", and is listed for a product card instead of being weakened silently. Running the cases needs the Playwright package and the real browser cache path; see the tests module.

A later sweep of every browser-gated file found two more stale cases: the Compute status line case still expected the wording used before the runner fallback showed counts, and the card drawer helper opened the edit controls before the card's own read replaced the read-only preview. Both now follow the shipped behaviour, the first by reading the line from the source. Three other cases (Deck shell stage, coworker cancel, Compute script) failed only on a slow disk and pass on a memory-backed one, so they are timing sensitivities of the run, not stale expectations.
