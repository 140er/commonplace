### Chat-platform bots (foundation built)

- `docs/design/chat-platform-bots.md` plans bots that people reach from a chat platform. A bot acts only as the linked person, in a channel it is narrower than on the web, every write needs the person's confirmation, and everything is off until the workspace owner installs and enables it.
- Slice 1 (card #455) is in: the workspace file `chat_bridge.sqlite3` (created only by the first install), sealed credentials (write-only, never in a response, log, audit row or tool result), the owner install routes under `/api/bridge/installs`, a credential test through the adapter interface that an install needs before it can be enabled, one install per platform team on a hub, the read-only `bridge_status` tool and the `commonplace bridge status|disable` kill switch. No platform adapter, linking, intake or turn exists yet: the public intake paths answer 404, and creating an install answers `unsupported_platform` until an adapter is registered. The code is `commonplace/chat_bridge/` (the name `bridge` was taken by the MCP client bridge).
