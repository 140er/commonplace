### Two timing-dependent tests no longer fail under load

Two tests from the pipeline and gateway-memory work failed in the changed-test checks after the first run had passed. The pipeline card-step test posted its gate event exactly five minutes ahead of the clock the server had frozen at fixture time, so any setup delay put the event past the five-minute limit and the whole request was refused. Its events now sit one and two minutes after the card claim. The gateway polling-growth test compared one 600-request batch to a limit of 1 MiB; a one-time lazy allocation of about 1.9 MiB (a first-use buffer) landed in that batch on a loaded runner and counted as growth. When the first batch exceeds the limit the test now measures one more batch and that one decides: retained growth repeats in the next batch, a one-off allocation does not. Neither change relaxes a limit or removes an assertion.

A third one: the person-token test that checks the event feed answer is unchanged after a deletion token is minted compared the whole answer, headers included. The Date header changes when the two requests straddle a second, so the identical answers differed once in a while. The comparison now leaves the Date header out; status, every other header and the body are still compared.
