### Host backup: a failing lvs never means "snapshot gone"

The LVM-snapshot host backup script treats only `lvs` exit 5 (volume not found) as proof that its temporary snapshot is gone; any other `lvs` failure counts as still present, so the run ends with the existing alert and a failing exit instead of a clean result, and cleanup keeps refusing to remove a volume whose origin it could not verify. The deploy README now says that `CHECK-PENDING` exits 0 (read the `result` line and the proof's `check_pending` and `snapshot_left` fields, not only the exit status) and that the script requires `BACKUP_HOOK`, `BACKUP_RESTIC_HOST` and `BACKUP_HOOK_LOCK_NAME` from the unit environment, with a drop-in example and the warning that a plain copy over an older wrapper fails every backup.
