### Bot learning extraction (slice S2 built)

- `extract.after_turn` is the one hook the turn engine calls, after a new turn finished with a stored `ok` reply (never for a replay, a stopped or a failed turn). It runs the model on its own thread after `done`, so the reply is not held. It does nothing unless the workspace switch is on, the bot's mode is `ask` or `auto`, the person is not paused and there are messages after the floor.
- A run starts when the person sent at least 3 new messages or one message with a cue (one table row per language: English, Dutch), the bot's last run is at least 5 minutes old and the person has no other run in flight. A run is claimed by the `(bot_id, upto_message_id)` journal row; one older than 60 seconds is closed `failed:interrupted` and its window is never rerun. No usable model or no unit left in the shared model budget means no request and the next turn re-checks.
- The extractor sees only the person's own main-thread messages (at most 6, 4,000 characters, redacted, JSON-quoted) and up to 30 topics of live items; never bot replies, tool results, event messages, thread messages of others or other people's items. Its answer must match a closed JSON schema (otherwise `failed:schema`) and at most 3 items count.
- Verbatim-span rule: the server stores an item only when its quote is a character-for-character span of the stored original message (8 to 300 characters, no redaction marker), the kind, topic and project tag are valid, the secret guard and the sensitive-category check pass, and the sentence was not forgotten. Anything else is dropped and only counted (`n_dropped`).
- Caps: 3 items per run, 20 new items per person per UTC day (counted from the log, so a forget gives none back), 200 live person items. A repeated sentence only bumps `seen_count`; new words for a known topic replace the old item (shown later as "earlier").
- `auto` stores the item `active`. `ask` stores it `proposed`: never used, replacing nothing until accepted (accept and reject come in a later slice), and deleted after 14 days unanswered. Showing items in the thread and using them in prompts are not built yet; with every switch off, which is the default, nothing is written and no model is called.
