### Bot learning retrieval (slice S3 built)

- When learning is on for the workspace and the person's bot (`ask` or `auto`, not paused), each turn reads the person's own active learned items that fit the new message and puts at most 8 of them (2,400 characters, whole items) into the prompt as a separate block labelled "Learned about the person", each with the date it was said. The words are quoted data: the prompt tells the model that the person's current message and its fixed rules always win over a learned item, and no item can call a tool or change a setting. With any switch off, or with nothing relevant, the prompt is exactly what it was before and nothing is read or counted.
- Relevance is full-text match on the new message, weighted down by half every 90 days since the item was last seen or used; pinned items never fade; up to three standing preferences or instructions come along without a matching word; an item unseen and unused for 180 days is no longer used (still listed, never deleted). An item tagged with a project is used only while the person can read that project. Another person's items are never read.
- The reply the person sees carries a reference to the items it used (ids only). The reference shows the items still there and omits any the person forgot; the use count and last use of those items update when the reply is stored. Forgetting an item removes it from the next turn and from the search index at once. Showing the items in the thread (Used: n learned items), accept and reject, and shared items come in later slices.
