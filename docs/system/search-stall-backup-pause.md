### A search never waits per call for a backup pause or a worker start

Round 2 of the search stall (14 Nov 2026). Live probes of three deploys showed searches running into the client's 60 s limit for about five minutes, one to eleven minutes after each container start, while the pages that do not read the palace stayed fast; the gateway logged `startup context unavailable (TimeoutError)` and a search-index job that never made progress (`threads=0 units=0`). Two durations matched the online backup's pause limit (300 s) and the third was the backup itself; the start of the stall is not "backup end + 2 minutes" but the backup's pause window, which opens a few minutes after the container starts because the backup runs after the health check and prepares first.

What the code does while the memory workers are paused: every worker call waits up to 20 s for the pause to end, then answers paused, and a search makes several worker calls one after another (the fact search, the search itself, the drawer read, the access proofs). Three waits of 20 s are a minute, and the answer after them was a generic 403 ("memory request refused"). The index job made the same calls, counted each refusal as a failure and backed off up to 60 s, which is the `units=0` that never finishes; and `initialize` waited as well, so the startup context was never reached or timed out. The same held for a worker that is still starting after a restart: each call waited up to 30 s behind the start, and the call that began it waited for the whole start (up to 120 s).

Decision: a person's request gets one wait budget (`COMMONPLACE_MEMORY_WAIT_S`, 5 s) for pause and start waits across all its worker calls. A pause met once is not waited for again; a start that outlives the budget finishes in its own thread. The answer is a retryable 503 with `retry_after_s` (and `warming_up` while a worker starts), never a 403 and never an empty memory. Index writes never wait for a pause and a refusal with a retry hint is not a failure for the job. Each refusal, and each wait of a second or more, logs one line with its bound. Not changed: the length of the backup's pause (it copies the worker files while paused and is limited to 300 s) and the lock bounds of the earlier round (`search-bounded-wait-on-index`), which stay.
