### Host backup: check-pending, leftover snapshots, no forced removal

The LVM-snapshot host backup script (`deploy/backup/`) separates a good upload from its integrity check: a repository that is only locked at check time yields `CHECK-PENDING` (exit 0), retried by `--retry-check` without a new backup, while a real check failure stays `FAIL`. Locks are cleared with a plain `restic unlock` only (stale locks; never `--remove-all`, forget or prune). A busy snapshot is never forced away: holders are logged from the mount tables, removal is retried a bounded number of times, and a snapshot still present ends the run with an alert and exit 1 (also after a pause-route fallback). A snapshot from an earlier run (own name pattern only) blocks the next backup with the same alert; nothing is deleted by that guard. Mount propagation was left unchanged because a namespace copy ignores it; installing the new script on the production host is a separate owner step.
