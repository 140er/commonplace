### Compute status line from existing reads

- Compute opens with a status line (running, waiting, stuck, last activity) and a job list. No backend was added: the counts come from the `agents.runs` part of `GET /api/topology/node` for each machine node recorded as a runner, and last activity from those runs plus the worker connection of the same read (owner view). Stuck means an unknown start outcome or a queued, leased or starting job older than thirty minutes; started jobs are never stuck by age. The enrollment fallback (no topology nodes) asks that same route for each enrolled runner machine by its id, which the route already accepts for a key the map does not hold, so the screen shows the same counts and list there. It says running work is not reported only when the route itself answers that it cannot report; a read that failed is worded as unreadable, never as zero. Gateways, Targets and Passive scopes moved behind an "Advanced" label with plain explanations.
