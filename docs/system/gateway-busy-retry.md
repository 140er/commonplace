### A locked database gives a retryable error, not "Internal error"

- Under SQLite write-lock contention (11 Nov 2026, three episodes) every authenticated MCP call returned a bare `-32603 Internal error` while `/healthz` stayed green, and a client could not tell whether its write applied. The gateway now logs the SQLite error and the tool name (never arguments) and, for a lock or busy error, answers `-32001` with `data.retryable: true` and `data.retry_after_s`, so an orchestrator waits and renews its lease. The control, board and orchestrator databases share one explicit 10 s busy timeout, and a short write transaction retries its lock acquisition a bounded 3 times (only an instant refusal; nothing is written before the retry). Other failures still return `-32603`. Card #420, completing #428.
