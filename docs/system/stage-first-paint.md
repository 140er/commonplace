### The Deck stage paints its final dim state first

The shell draws the page chrome, including the Deck stage, as soon as the person is known and before the route is settled or any board, needs or roster read has returned. The stage used to read `state.base` for its dim state, which is still the Home address at that point, so a deep link to Today, Board, Memory, Compute, Bots, Settings or a card started undimmed and flipped to dimmed one to two and a half seconds later, a visible flash on phone and desktop. Until the first route has run, `navigation()` now reads the address (the Home address resolving to the Deck home), so the first paint already carries the value it keeps. After the first route nothing changes: the stage follows `state.base`. All routed screens share this one cause and are fixed together; an unrecognised address that falls back to Home once data arrives is the only case that can still change the stage once. The browser-free harness `tests/deck_stage_first_paint.mjs` fails on the old behaviour for every deep link.
