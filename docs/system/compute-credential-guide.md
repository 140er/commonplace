### Compute credential guidance lists references and shows the documented step

- The gateway and target forms now list the workspace's existing credentials to select from, instead of only asking for a typed reference. The list is a new read-only owner route that returns only name, purpose, account, version, recorded state and expiry; it reads the plain reference columns of the credential file and never opens its wrapping key or any key. Decision: credentials are still not created or entered from the browser. When none exist, or a reference is missing, revoked, expired or for the other kind, the form says so in plain words and shows the one documented operator step to create a credential, ready to copy; saving by typing a reference by hand keeps working.
- A gateway or target can now be saved without a credential. A credential is bound to the gateway or target ID, which the server assigns when the record is saved, so the reference cannot exist before the record. Decision (project owner): the record is created first and the credential is bound to its ID right after. The form says this in plain words; the saved record shows "No credential bound yet" in the list and in its details, and the same screen then offers to bind one, by choosing a listed credential or by using the copyable step, which is filled with the new record's own ID. The server refuses to verify such a record or use it for a run, proposal, script or passive collection (`credential_not_bound`) until a credential is bound; binding happens once and a bound record is never changed. Existing records and typing a reference at creation work as before, and the same owner permission applies.
- The copy button counts a missing clipboard, or a copy that does not return a promise, as a failed copy and shows the fallback text instead of "Copied.".
