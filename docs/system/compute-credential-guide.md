### Compute credential guidance lists references and shows the documented step

- The gateway and target forms now list the workspace's existing credentials to select from, instead of only asking for a typed reference. The list is a new read-only owner route that returns only name, purpose, account, version, recorded state and expiry; it reads the plain reference columns of the credential file and never opens its wrapping key or any key. Decision: credentials are still not created or entered from the browser. When none exist, or a reference is missing, revoked, expired or for the other kind, the form says so in plain words and shows the one documented operator step to create a credential, ready to copy; saving by typing a reference by hand keeps working. Known limit, for the project owner: a credential is bound to the gateway or target ID, which the server assigns when the record is saved, so the step needs that ID and a credential cannot be bound before the record exists.
