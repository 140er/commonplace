### Cold route modules and first-hit API work

The authenticated shell previously waited for every controller's static imports before requesting identity. The entry now imports shared shell helpers and selects route controllers on navigation. The asset response emits a flat `modulepreload` closure for the shell; an asynchronous route selector preloads only the current route's closure alongside it, without blocking the entry if prefetch fails. Closed chat panes load their transcript controller when opened. Card and Space decision history loads its shared event renderer even when Decide has never been visited. Imports share an in-flight promise and failed imports can retry. A route generation check rejects late navigation completions. Direct card and classic default routes resolve against the cheap shell directory; project cards and that directory load in parallel.

All 23 existing stylesheet links retain their original document order before `deck-prepaint.js` and `app.js`, including chat before Workbench and the final Deck overrides. Only JavaScript controllers are deferred: global CSS preserves the entrypoint contract and prevents unstyled route content or a changed cascade. The route readiness helper reuses loaded links without appending duplicates; a missing stylesheet still gets a ten-second deadline and explicit Retry. The browser fixture checks all 23 styles are ready at the first shell insertion and when the route's key element appears. The initial document shows “Loading Commonplace…” until identity resolves; only a real 401 selects sign-in. The first `/api/me` attempt still gets ten seconds after module evaluation, followed by three three-second attempts with 1/2/4-second backoff. The short optional bootstrap API budgets remain three seconds; ordinary card, memory, list and search budgets remain unchanged.

Static files use content ETags and `Cache-Control: no-cache`; matching validators return 304. A file whose name actually contains its content hash gets `public, max-age=31536000, immutable`. This change uses unbundled modules and revalidation, without a generated bundle or a build dependency.

Public script, style, font and image GETs use a separate 6,000/minute per-IP token bucket, including requests with a valid session. They no longer spend the 600/minute HTML/provider or authenticated API budgets. Credential paths are excluded even when their names have an asset suffix. Every API, credential, write and short-link policy retains its limit and identity. A fixture replays twelve 56-asset cold loads from one IP; develop refuses them with 429 for anonymous and signed-in callers. The generous asset ceiling still returns 429 with Retry-After when exhausted, without affecting API admission.

A module fetch can fail before any application code or identity request runs. The entry response therefore inlines a small independent guard, allowed by its exact CSP SHA-256 hash without enabling arbitrary inline scripts. A required module's 429, server or network failure shows “Could not reach Commonplace, retrying...” and Retry. Full document reloads clear the failed module map with 1/2/4-second backoff, limited to three retries in a minute; only a retry count/time is stored in session storage. Blocked storage leaves manual Retry instead of an infinite reload loop. A separate thirty-second module watchdog covers a stalled graph and stops when boot starts; it does not consume the identity request's ten-second budget. Application rendering clears the guard's retry state. Until a real identity 401, the static document has no sign-in form. The browser fixture rejects a required module with 429, 503 and a network abort and checks recovery through Retry; existing identity harnesses retain the 401 and transient-request cases.

The API trace found repeated first-hit work rather than a memory-worker dependency: card projection joined each row individually, then created each missing share link in its own transaction; the roster's decision badge built unrelated setup attention; the queue rechecked the same wing for every card; and an initial owner event read replayed all historical rows. Card joins are now batched, URLs share one transaction with lookup batches of 400, wing checks are scoped to the request, and the badge requests the card-only queue. The initial owner feed selects the latest 200 rows with the workspace/sequence index, returns ascending order and advances to the current cursor. Incremental reads and member ordinal feeds keep their existing semantics. Optional shell lists retain their existing client-side stale-while-revalidate behavior; authorization and complete card contents are never replaced by a shared stale projection.
