### Role model default and the never-silent rule

Card #419, with the settings slice of #387. Decision: a role (Coworker, builder, reviewer, gate) with no project or workspace model choice starts on a documented default instead of being refused: the first model in the project's model list, in provider then model order. The runner reports no per-role default to the hub, so the list is the one source every user shares and nothing is hardcoded. The job records `model_source` (`project`, `workspace`, `default` or `escalation`) next to the model and `model_reason`, and the start reply carries it.

Rules it keeps: a start is refused as `model_unresolved` only when no choice and no listed model exists. The owner then sees exactly one Needs me item per project (all missing roles named, a button to Agent models, nothing for members or agents) that clears itself when a model is added or chosen; a config role that names no `model_role` keeps its own item because no setting fixes it. Project settings and the Coworker config render show, per role, the model it runs on, labelled as chosen for the project, chosen for the workspace or default; an unknown state reads "Not known yet" and no usable model reads "No usable model", never an empty field.
