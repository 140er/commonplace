- **Owns:** How the HTTP worker's request lock treats a person's palace read and a background index write (`internal/write_mirror_units`). A read waits for the lock at most `MEMPALACE_READ_LOCK_WAIT_S` (default 5 s) and then answers a retryable `-32001` busy error whose message starts with `Memory is busy indexing` (`mempalace.deadline.BUSY_INDEXING`) and whose `data` carries `retryable` and `retry_after_s`. An index write takes the lock politely: it is never counted as a waiting writer, so a read that arrives behind it is not held back, and it enters only when no read runs or queues. It waits for that at most `MEMPALACE_MIRROR_LOCK_WAIT_S` (default 10 s) and then answers the same retryable busy error without writing anything; between units and around embedding it gives the lock back and takes it again the same way, within the same bound: when the lock cannot be taken back in time the request ends with the retryable busy answer (the units already written stay, nothing is written without the lock) and the index job replays the batch. A read that gave its lease up around embedding is bounded by the read wait in the same way.
- **Promises:** A search waits on an index write for one unit's write at most, and never for the write's whole run or for a slow search ahead of it; results of a search that runs are exactly what they were. Units are idempotent, so a refused or interrupted batch is replayed whole by the index job. The abort is a `BaseException` internal to the worker, so a broad `except Exception` in the embedding or write code cannot carry on without the lock. Typed association reads (`internal/read_associations`) keep waiting without a bound, because a busy answer there would hide a hit; every other palace read is bounded.
- **How it fails:** A palace held longer than the read bound answers busy (retryable) instead of stalling; nothing is dropped and the next search answers normally. An index write that finds the palace never quiet is refused after its bound and the job backs off as for any refused write.
- **Tests:** `tests/test_search_lock_bounded_wait.py` holds the lock the way a slow index write does, queues a write behind a slow search, keeps the palace busy between index units and after embedding, and checks the bounded answers and that the lock stays intact, that the write finishes whole, and that an idle palace writes as before; `tests/test_commonplace_memory.py` runs it through the real route and worker.
