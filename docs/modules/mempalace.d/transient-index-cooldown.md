- **Owns:** What `mempalace_search` does when its vector search meets a transient index error (the HNSW flush window): one search per cooldown (`MEMPALACE_TRANSIENT_RESET_COOLDOWN_S`, default 30 s) drops the palace caches, waits 2 s and searches again, as before; a search that meets the error again inside the cooldown is answered at once from the lexical index and carries `index_catching_up: true`. The worker also logs one line, `search timings: vector-probe …, first search …, index error …`, for any search whose probe and first search took a second or more (timings only, never the query or results).
- **Promises:** At most one search per cooldown pays the cache drop and the wait, and no search waits while a flush window lasts; the lexical answer is the same one a diverged index already gets, flagged, and the next search after the window sees the vector index again. A first search in a window and a search whose retry succeeds behave exactly as before (`index_recovered`).
- **How it fails:** A lexical answer inside the cooldown can rank differently from a vector one; the flag says so. A palace with a persistent flush window answers lexically except for one vector retry per cooldown.
- **Tests:** `tests/mcp/test_search_transient_cooldown.py`.
