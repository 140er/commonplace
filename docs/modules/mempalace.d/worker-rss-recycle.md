- **Owns:** `mempalace/worker_memory.py` owns the memory readings (a process's RSS split into anonymous and file memory from `/proc`, the container's cgroup v2 split from `memory.stat`, `memory.current`, `memory.max` and `memory.events`) and the worker's RSS recycle: a watchdog thread that asks the generation coordinator to drain with the reason `rss`.
- **Promises:** The recycle is off unless the launcher sets `MEMPALACE_WORKER_RSS_RECYCLE_MB` (a whole number of MiB of at least 512; anything else is ignored with a warning). Only anonymous memory counts, since file-backed pages are the kernel's to reclaim. A worker is not recycled before ten minutes of uptime or before it has admitted two calls (the restart circuit counts a recycle after one admitted call as a failed start), and over the ceiling it waits for a moment with no call running unless it is a quarter over. A drain finishes every accepted call, refuses new ones with the existing recycling answer, and exits; the gateway starts the replacement on the next call. The readings never raise: an unreadable file is an unknown figure.
- **How it fails:** Where `/proc` or the cgroup files are absent the readings are unknown and the watchdog never fires. A sample that fails is skipped and tried again at the next interval.
- **Tests:** `tests/test_memory_growth_bounds.py` covers the ceiling parsing, each condition that holds a recycle back, the drain with the `rss` reason accepted by the parent without counting a failure, the worker loop starting the watchdog, and the cgroup and process readings.
