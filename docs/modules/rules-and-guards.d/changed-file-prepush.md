- **Owns:**
  - The changed-file pre-push check runs canonical Ruff checks and real mypy with untyped function bodies checked, retains Rust formatting, documentation validation and mapped tests, and measures elapsed time against a nine-second alarm.
- **Promises:**
  - The alarm never kills or omits work. Missing tools, failed documentation comparison, invalid push input, another pushed checkout or dirty tracked files block the push. Existing type errors remain visible; no ignore rules are introduced. Matching changed `.py` and `.pyi` roots use separate mypy invocations, retaining checks of both files without a duplicate-module collision.
  - Mypy uses explicit package bases from the repository working directory, so changed namespace modules and imports such as tests.helpers share one module identity. Every changed Python root and untyped-body checking remain enabled; no package marker, ignore or exclusion is added.
  - `guards/hooks.py stage-pre-push` prepares a fresh directory without changing configuration or existing hooks. Existing executable hooks forward to their previous paths; absent or disabled hooks stay absent, preserving Git's default behavior, including clean checkout updates and dirty-receiver refusal under `receive.denyCurrentBranch=updateInstead`. Stage again when the set of enabled hooks changes. The prior pre-push receives the same arguments and stdin and retains its refusal. Activation and exact configuration rollback are separate reviewed steps.
- **How it fails:**
  - Staging refuses a relative `core.hooksPath` before creating files or changing configuration: Git resolves ordinary and receive hooks from different directories. Audit both hook sets before changing such a configuration. The default hook directory and absolute custom paths remain supported.
  - Full imported typechecking and mapped tests can exceed the elapsed target. Python typechecking does not claim coverage of untyped JavaScript or Rust; their existing checks remain. A push containing another commit must check out and validate that commit before proceeding.
- **Tests:**
  - `test_guards_prepush.py` checks non-cutting alarms, late test failures, actual typechecker arguments, missing tools, dirty tracked bytes and private malformed-input diagnostics. `test_guards_hooks.py` exercises real Git pushes with real formatting, lint and type mutations, spaces, deletions, a new branch, chain refusals, exact stdin replay and unchanged original hooks/configuration. Real mypy pushes accept a valid implementation/stub pair and refuse an actual type error in either file. Real `updateInstead` pushes verify checkout updates and dirty worktree/index refusal with absent or disabled `push-to-checkout`, plus preservation of existing custom and relative-path receive refusals.
