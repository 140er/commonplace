- **Owns:**

  - Sharing and members' private threads (slice S3): `routes.py` serves `GET`/`POST /api/bots/<id>/shares`, `PATCH`/`DELETE .../shares/<user>` (owner only, web session only, idempotent, ids-only `bot_share:set` audit row per real change), `GET`/`POST /api/bots/<id>/threads`, `PATCH .../threads/<tid>` (private threads only; `visibility: shared` answers `409 not_available`) and `GET`/`PATCH /api/bots/settings` for the workspace switch. Messages, stop, confirm and read take `?thread=` and default to the caller's own thread (the owner's original thread, or a member's private one opened on first use); a member's memory notes are theirs (`?own=1`), the owner's are bot-level. `BotStore` reads and writes of messages, leases, actions, pending confirmations, work, forwards, memory and unread marks take the thread and go through `reach` (`_scope`); the owner's original thread (thread id None) is unchanged. `bots.roster` returns the person's own bots then the shared bots they hold a live share of, with `mine`, `shared`, `owner`, `perms` and `frozen`; unread is per person and thread (`bot_reads`). `TurnRun` carries the thread, keys its lease and journal per thread (`journal_key`), re-resolves the share before every model request, tool call and reply (`failed:revoked`), and `limits.Registry` admits one turn per thread and four per bot. `updates.py` posts a filed task's or forwarded reply's event to the filer's thread only while that person's share holds.
