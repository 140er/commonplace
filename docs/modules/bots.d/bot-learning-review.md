- **Owns:**

  - The learning memory, slice S5 (review and the app grant): `learn_review.py` is the review part of `Learned` (`accept`, `reject`, `bot_names`, and `group`). A proposal (ask mode) is accepted into an active item (it replaces an older item of its topic, needs the workspace switch, and a second answer is a 409) or rejected (a real delete of the row and its index entry, the same sentence blocked from being proposed again, one `reject` log row); both are the person's own, anything else is 404. Every item the list returns carries a `group` (person, shared, proposed, earlier, old) and a `source` (bot id and name, source message id, date), so one list shows each item with where it came from and its scope; notes appear as kind `note`. `POST /api/learned/<id>/accept` and `/reject` sit next to the existing edit, pin and forget routes.
  - Blocks: `blocks.learn_proposal` hydrates `{type, id}` with the reader's own rights into the item (`open` while proposed, `accepted` once active; a rejected, forgotten, foreign, note or unreadable-project item is `gone`); `blocks.learned` adds `how` (`used` or `learned`) and `at` to its items. `extract._announce` posts one `event` message after a run that stored something new (a repeated sentence announces nothing): one `learn_proposal` block per item in ask mode, one `learned` block in auto mode, with a fixed sentence; the block holds ids only, never words. The thread shows Accept, Reject, Edit and Forget on those blocks (`bots.js`), and a review sheet from the bot sheet lists everything grouped with source, pin, edit, forget, pause or resume (7 days) and forget-everything with a second tap.
  - Tools in `tools_learning.py`, offered only to the person's own bot and only while the workspace learning switch is on (so a default workspace sends exactly the tool list it always sent): `learned_list` (read, the asker's own items, at most 20, ids kept readable through `Result.keep`), `forget_learned` and `forget_all_learned` (confirm tools: the chip label is built from the stored item or the counts, nothing is deleted before the tap, a foreign id gets no chip), `pause_learning` (routine, 1 to 30 days, only pauses). No learning tool takes a user id, turns learning on, widens a mode or edits text.
  - The `bots:learned` scope (`bots_grant.LEARNED_SCOPE`): a read-only grant on top of `bots:chat` for the person's own app, granted like `bots:confirm` (a PAT through Settings > Agents or `PATCH /api/connections/<id>` with `bots_learned`; OAuth through a ticked box; never the command line or a person session; useless without chat, withdrawn with it). With it an app may call only `GET /api/learned` and `GET /api/bots/<id>/learned`; every write on the learned routes is 403 `read_only` (and recorded as a refused `bots.write`), and every other learned route stays 404. Without it, apps, agents and machine credentials get 404 on all of them as before.

- **Promises:**

  - Reject is a real delete; accept never changes the words; a model can ask to forget but only the person's tap deletes; the read scope never changes anything.
