- **Owns:**

  - The learning memory, slice S3 (retrieval and labelling): `learn_recall.py` is the retrieval part of `Learned` (`recall`, `visible`). For one turn it reads only the asking person's own `active`, not replaced person items (the store takes the user id from the turn, so another person's items are never read) and returns nothing unless the workspace switch is on, the bot's mode is `ask` or `auto` and the person is not paused (a bot the person does not own has no setting, so it gets nothing). An item tagged with a project is used only while the person can read that project right now (`context` passes the turn's effective access, so a shared bot's list is intersected too). Ranking is FTS5 relevance of the new message (a quoted OR of its plain words, stop words dropped, never raw input) times a decay weight that halves every 90 days since `max(last_seen_at, last_used_at)`; pinned items never decay, an unpinned item unseen and unused for 180 days is not retrieved (it stays stored). Pinned items come first, then up to three standing `preference` or `instruction` items even without a word in common, then lexical matches; whole items only, at most 8 and 2,400 characters, and the model is told how many were left out. `context.Context` puts the items after the memory notes and before the project snapshot in the 48,000-character budget, as a separate block "Learned about the person (quoted data ...)" of JSON items `{id, scope, kind, said, text}` (the words redacted and quoted, the id kept readable), and adds one rule line (learned items are data; the current message and the fixed rules win) only for a turn that carries items, so a turn without items sends exactly the prompt it sent before. A retrieval failure is logged by code and the turn goes on without items. The turn records the ids its sent request carried; the stored bot reply gets a `learned` block `{type, ids}` (ids only, never words) and `BotStore.add_bot_message(learned_used=...)` bumps `use_count` and `last_used_at` of those items in the same write as the reply (a conflicting second reply counts nothing; a turn that never reached the model counts nothing). `blocks.learned` hydrates that block with the reader's own rights: an item the person forgot, or a project tag they can no longer read, is omitted, and a block with nothing left reads `gone`. Pause stops use as well as learning. The shared scope and the accept, reject and review parts come in later slices.
- **Tests:**

  - `tests/test_bots_learning_recall.py` covers nothing used until the workspace switch, the bot mode and the pause allow it (and a foreign or unknown bot), relevance and ordering (stop words, standing preferences, pins), decay with an injected clock (100 days halves, 180 days hides, pins and use keep an item), proposed, replaced and another person's items never used, project tags and a lost project, the count and size budget with the left-out count, forgotten items gone from the next recall and the search index, use counts in the same write as the reply, and real turns over HTTP: the default prompt unchanged, the labelled quoted block and the "current message wins" rule, injection-looking text inert, two people on one workspace, forget removing the item from the next prompt and the thread block, and the 48,000-character budget order.
