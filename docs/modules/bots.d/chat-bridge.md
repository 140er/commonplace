- **Owns:**

  - A turn has a surface (card #455, slice 3). `TurnRun` and `tools.Turn` take `surface` (`web` by default, or `dm` / `channel` from the chat bridge) and `disclosure` (`titles` or `full`, channel only); the web path sends exactly what it sent before. `tools.surface_allows` narrows the tools offered: `dm` gets no routine tool unless the person confirms by tap (`Turn.tap`, set from the link's `confirm_ok`; slice 4): then the routine writes that carry a `chip` line (`create_work`, `comment_work`, `tell_orchestrator`, `prioritize_work`, `remember`, `forget`) are offered, and `tools.effective_kind` makes them confirm tools on `dm`, so a call freezes a pending action (with the future-tense `chip` text as its label and the same "your own words" check before the chip exists) and writes only when `confirm` runs after a tap; the other confirm tools leave their chip in the person's web thread. `tools.CHAT_TAP` and `CHAT_CONSEQUENTIAL` name the tools a chat tap may confirm and the three that need the owner's switch, `channel` gets read tools of the one project only, with `titles` just `project_status` and `list_work`. A channel turn also gets no memory notes, no earlier messages, no learned items and no persona instructions, the system prompt says the reply is public to the channel, and no learning runs after it.
