- **Owns:**

  - The learning memory, slice S4 (shared scope): `learn_share.py` is the shared-scope part of `Learned` (`share_check`, `share`, `shared_list`, `delete_shared`, `shared_on`). A shared item is a copy of one of the person's own active, current items (`scope = shared`, `board` = the project, `shared_from` = the person item, same quote, source link and `user_id`; the bot's own note is not copied). It exists only after the person's tap on a `confirm` chip and only while the workspace `shared_enabled`, the project's `shared_enabled` and the reader's access to that project all hold; every read (`shared_list`, retrieval, the thread block) re-resolves all three, so switching one off hides every shared item at once and switching it back on restores them, and a reader who cannot read the project gets 404 from the list and nothing in a prompt. A project holds at most 50 live shared items; sharing the same sentence into the same project twice is a conflict. `tools_learning.py` registers `share_learned` (a `confirm` tool, `reach none`, offered only to the person's own bot while the workspace has learning and sharing on): the model supplies an item id and optionally a project, the item must be the person's own and the project readable, and the chip label is built from the stored item (the exact words, the project name, "with your name", how it is deleted) so no model text reaches it; nothing is copied until the tap runs the tool, which checks the item, the project and both switches again and refuses with a plain sentence when one is off (the chip is then closed). `build_pending` makes the same chip for `POST /api/learned/<id>/share` (`{project?}`, defaulting to the item's project tag; the tap is the existing `POST /api/bots/<bot>/confirm`, so a second tap is 409). `learned_routes.py` adds that route, `GET /api/projects/<slug>/learned` (shared items for a member who reads the project, each with the sharer's address and `mine`; 404 for an unreadable project, empty while a switch is off) and lets `DELETE /api/learned/<id>` remove a shared copy: its sharer, or a workspace owner who can read the project; anyone else gets 404. Deleting a copy never touches the person's item and writes no block hash; forgetting the person's item (or "forget everything" of its bot) deletes every copy (`Learned._delete`) and blocks the sentence. Retrieval (`learn_recall.py`, `context.py`) adds the shared items of the bot's own project (for a bot without one, of the projects the person reads) to the candidates, only when the reader's own bot has learning on; they are taken only on a word in common, at most 3 per turn, ranked and decayed like the person's items, reserved a place inside the 8-item budget, and shown as `{id, scope: "shared", kind, said, text, by: "you" or "a teammate"}` (never a name) under one extra explanatory paragraph; the reader's own copy is skipped when its source item is already a candidate. `BotStore.add_bot_message(learned_used=...)` counts a shared item's use on the copy, and `blocks.learned` hydrates shared items for any reader who may still read them.
- **Tests:**

  - `tests/test_bots_learning_shared.py` covers the shared scope on a clean workspace (owner, member, a readable project and a private one): sharing off by default with no tool offered and no chip, each of the three switches in turn refusing a chip with a plain sentence, a chip alone sharing nothing, decline, a second tap and another person's tap refused (409, 404), a switch turned off between chip and tap closing the chip, the exact chip label, a shared item reaching a teammate's prompt labelled and quoted while the private item never does, the person's item unreadable by others, a reader whose bot has learning off getting nothing, project bots reading only their own project, the three-item cap with the left-out count, switch-off hiding and switch-on restoring (project, workspace shared, workspace), a member who cannot read or loses the project, sharer and owner delete rights (and no one else), forgetting a person item or everything removing the copies (row, index, block hash), the model only able to ask, and the store refusals (wrong person, unreadable project, copy of a copy, edit of a copy, note not copied, the 50-item cap, list switches).
