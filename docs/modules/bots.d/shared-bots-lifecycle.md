- **Owns:**

  - Lifecycle (slice S5): `lifecycle.py` is the lifecycle half of `BotStore` (`LifecycleMixin`) and the control-side hook. `member_removed(gateway, workspace_id, user_id, actor_id)` is what a removal path calls once the membership row is gone (the control database has no removal path yet): it never creates a bots file, ends the person's live shares with `member_removed`, freezes the bots they own (`frozen_reason = owner_left`), cancels their open confirmations and writes one ids-only audit row `bot_lifecycle:set`. `sweep` applies it to people who left without it (run by the roster and the workspace list). `disable`/`enable` freeze and lift a shared bot (`frozen_reason = disabled`); `adopt` hands a frozen shared custom bot to a workspace owner: new `user_id`, access list and shares kept, one `adopt` log row, `access_version` bumped, `thread_floor` set to the newest message so the old owner's original thread (thread id NULL, append-only) is unreadable to the adopter (`_scope`, `Reach.read_from`, `messages`, `roster`, request-id and reply lookups all honour it), legacy work and forward rows (no person) pinned to the old owner, the adopter's own old share ended. A freeze or a lift is one `freeze` row in the access log (`ref` the reason, `mode_after` `frozen` or `lifted`). `Reach` already answers `Missing` to members and a read-only `Reach` (`frozen`) to the owner of a frozen bot; `TurnRun._live` now stops owner turns too, `share` and `access_set` refuse a frozen bot, and `POST messages` checks `reach.can_write` for a shared or frozen bot (an archived shared bot takes no new turn). `lifecycle_routes.py` serves `GET /api/bots/shared` and `POST /api/bots/<id>/disable|enable|adopt` for workspace owners in a web session (everyone else 404).
