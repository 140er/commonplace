- **Owns:**

  - Shared threads and the audience rule (slice S4): `POST /api/bots/<id>/threads` with `visibility: shared` opens a shared thread (`BotStore.thread_open`; the bot must be shared, at most `MAX_SHARED_THREADS` open per bot). `BotStore.audience` names the other people who read a shared thread (live `see_shared` members and the opener) with the newest `history_from` among them; `tools.Turn.effective` feeds their fresh principals to `access.effective`, which intersects the reach with each of them (`Access.audience`, `limited`, `readers`), `Turn.board` and `access.check_tool` refuse a limited project with `AudienceLimited` (`audience_limited`, fixed sentence), `tools.audience_gate` does the same before schema validation, `Turn.machines` narrows machines by every reader, and a shared-thread model is only offered `access.projects`. `TurnRun` drops history older than the audience floor, reads only bot-level notes (`memory_for_turn(..., shared_thread)`), skips learned items, and before storing a reply withholds it (`failed:audience`) when a project it used is no longer readable by every reader. `updates.py` posts generic, title-free event text in a shared thread and does not copy a forwarded post's answer. Messages in a shared thread carry `author` (the route adds it), request ids are checked against the author, `read_only` readers get 403, and `stop` only stops the asker's own turn.
