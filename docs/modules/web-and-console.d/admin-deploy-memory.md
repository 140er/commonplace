- **Owns:** `memory_view` in `commonplace/web/admin.py` builds the `memory` object of `GET /api/admin/instance/deploy`.
- **Promises:** `memory.cgroup` carries the container's `current_bytes`, `limit_bytes`, `anon_bytes`, `file_bytes`, `shmem_bytes`, `inactive_file_bytes`, `working_set_bytes` and `oom_kill`; `memory.gateway` the gateway process's `rss_bytes`, `anon_bytes` and `file_bytes`; `memory.worker_count`, `workers_rss_bytes` and `workers_anon_bytes` the totals over all running workers; and `memory.workers` the fifty largest workers with `workspace_id`, `pid`, `uptime_s` and their memory. Every figure is read-only, taken from a few small files, and null where the platform does not give it.
- **How it fails:** A failing reader leaves `memory` null (or a figure null) and the rest of the deploy view unchanged; it never raises.
- **Tests:** `tests/test_admin_instance_api.py` covers the cgroup split, the gateway and per-worker rows, the bound on listed workers and a failing reader.
