- **Owns:** The history and handoff page (`web/static/history.html`, `history.js`, `history-page.js`, `deck-history.css`) and its one entry link, "Saved threads", beside Map on the Deck Memory page (`deck-memory.js`). It lists saved threads from `GET /api/handoffs`, opens one with `GET /api/threads/<id>` and `/chain`, and offers the handoff action from `GET`/`POST /api/handoff/start`.
- **Promises:** The chain section states exactly which history a new agent would use (the saved threads, newest first, their message counts, and where the chain ends), links each to its verbatim messages, and says nothing is summarised. The action shows only when the server says `ready`; a review step names the destination, the thread it continues and what is carried over before anything starts, and the typed note is shown exactly. An unavailable, unknown or failed state always names why and a next step, and is never an empty panel. Saved words are escaped, never summarised, and no user text goes through a replacement-pattern `String.replace`. Only a 401 reads as signed out; a timeout or other failure reads as a failed request that changed nothing.
- **How it fails:** A thread that is missing or not readable shows one "not available to you" answer with no hint which. A chain that cannot be read leaves the thread and the action visible with a reload hint. A late answer to an earlier load cannot replace a newer one.
