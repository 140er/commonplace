- **Owns:** `app.js` (`cardAdded`, the card-route panel in `route`, `escapeInPanel`) and `loading.js` (`showLoading`) make Add card land on the new card. The form closes at once, the new card is put into the board list without waiting for a refresh, becomes the selected card, and the board shows the column it landed in (on a phone that column is the active pill, in the Deck look a notice names it, because the Deck has no Todo column). `board.js` exports `cardColumn`; `deck-board.js` draws the notice.
- **Promises:** The side panel only ever shows the card the address names. While that card's read is in flight the panel says "Loading card…" and never keeps the previous card or a Needs me detail with its live buttons. A screen or card read that takes longer than one second adds a plain "Still loading" line next to the progress text. In the Deck look the logo goes to Home without waiting for the project list. Escape closes the open card, also from a field inside it; text typed in that field is kept, so the first Escape only leaves the field.
- **How it fails:** If the new card's own read fails, the panel shows the read error with a Close button, as before; the board still shows the new card until the next refresh replaces the list. A refresh that drops the card (a permission change) removes it from the board like any other card.
- **Tests:** `tests/board_add_card_selection.mjs`, through `tests/test_board_add_card_selection.py`, runs the shell's own functions against the real board renderer and covers add, stale panel, Escape, logo route and loading hint, with mutation tests that undo each fix. `tests/test_board_add_card_selection_browser.py` repeats the journey in a real browser where one is installed and skips cleanly elsewhere.
