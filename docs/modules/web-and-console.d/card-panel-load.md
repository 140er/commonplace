- **Owns:** `app.js` (`openingCard`, the card-route panel in `route` and `cardPanel`) and `details.js` (`renderCardPreview`, `showCardPreview`) open a card in the Deck in two steps. The panel draws at once, in the drawer's own shape, with what the lists already hold (title, state, holder, summary) and a "Loading card…" line; the card's own read starts in the same moment, beside the project refresh instead of after it, and a known card is drawn in full as soon as that read answers. `deck-board.css` keeps every board column at 220 px or more, so the board scrolls sideways instead of squeezing.
- **Promises:** Opening a card never waits for the project refresh, needs-me or the roster before showing something. The preview holds no control that writes; the actions arrive with the read. A card the lists do not know (a shared link) shows the progress line alone and is drawn after the refresh that names its project. With the panel open or loading, at 1280 px and 1024 px, no board column is narrower than 220 px; a phone keeps its full-screen panel.
- **How it fails:** If the card's read fails, the panel shows the read error with a Close button, as before. A read answered after the person moved to another card or screen is dropped. The preview comes from the last list, so its state can be one refresh old until the read answers.
- **Tests:** `tests/test_card_panel_load_browser.py` holds the card read and the project refresh in a real browser (skips where none is installed) and checks the known fields before the read, the full card before the refresh, and the column width at 1280 px and 1024 px, red on the previous panel.
