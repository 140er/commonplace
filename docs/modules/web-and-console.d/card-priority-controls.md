- **Owns:** The isolated `web/static/card-priority.js` presentation, lazy attribution reads, owner priority actions and Undo notice, integrated into board, Deck, card details and the existing actions menu.
- **Promises:** All cards distinguish unranked normal from person- or Coworker-chosen priorities. Hover and keyboard focus expose attribution; the card view shows recorded reasons. A person-chosen creation priority retains its creation actor after unrelated edits or moves; actual later priority changes take precedence. Owners choose one of the four server-supported levels; members read only. The independent priority filter composes with existing board filters.
- **How it fails:** Failed writes retain the old level and explain the failure. Undo restores only the former level as the owner's explicit choice, using the successful write's returned version; a stale Undo cannot overwrite a later edit. History reads are scoped to the mounted board and card version. Styles use the existing constructed-sheet convention, without inline style attributes.
- **Tests:** `tests/test_card_priority_controls.py`, `tests/card_priority_controls.mjs`, `tests/test_card_priority_controls_server.py` and `tests/test_card_priority_controls_browser.py` cover actions, attribution, filtering, authorization, failure retention and stale Undo.
