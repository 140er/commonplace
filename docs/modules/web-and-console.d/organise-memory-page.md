- **Owns:** The organise memory page (`web/static/organise.html`, `organise.js`, `organise-page.js`, `deck-organise.css`) and its one entry link, "Organise memory", beside Saved threads on the Deck Memory page (`deck-memory.js`, `deck-memory.css`). Three views, chosen by `?view=`: Facts, Stored sources and diary, and Links.
- **Promises:** Facts show subject, predicate and object with start and end dates, wing, sensitivity and sources; an ended fact stays listed as history. Sources list places from the taxonomy, show the start of each stored text and open the whole text exactly as stored (diary entries are the room named "Diary entries"). Links show both ends with their wing and room, the label and the use count, and list the automatic links inside a wing for reading only. Ending or replacing a fact and adding or removing a link each show a review first: what happens, what stays, the typed value verbatim, and then "Confirm" or "Cancel, change nothing"; cancelling sends nothing. The page has no delete, bulk or by-source action. Every empty or unknown state says why and what to do; user text is escaped and never goes through a replacement-pattern `String.replace`.
- **How it fails:** A refused or failed change keeps the previous state on screen and says so, with a reload hint when the stored state moved. A timeout reads as "cannot tell whether anything changed", never as signed out and never as "nothing changed". Only a 401 reads as signed out; a 403 shows the server's reason; any other failed read is an error with "Try again", never an empty list. A late answer to an earlier load cannot replace a newer one.
