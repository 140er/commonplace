- **Owns:** `deck-coworkers.js` also words every state of the Coworker page. `botStatus` turns a bot's own roster row (disabled, waiting on you, working, last message) into one line; `workStatus` combines it with the conversation's jobs; `rowSummary` words the list row, so each Coworker row carries the bot's state and a line instead of an empty summary.
- **Promises:** In every state the Working on line says what the bot does now or did last, or why that is not known: how many decisions wait on you (with a link to Today), that filed work is in progress (with a link to the project board), the last message and when, a disabled bot or one that needs a new owner, "No run recorded for this bot yet", and for a member of a shared bot that the owner's other work is not shared with them. A finished run with no summary says so about the run, and hidden progress says the card is not shared. A waiting decision outranks an old finished run; a running job outranks everything. While a conversation loads the line reads Loading and after a failed read Not available, never Idle.
- **How it fails:** Only the roster row, the conversation's own jobs and the project checkpoint are read; nothing is invented. A bot the roster does not list falls back to "No run recorded for this bot yet". The wording "No summary recorded" no longer appears next to any work.
- **Tests:** `deck_coworker_empty_states.mjs` mounts the page once per state (owner, member, disabled, waiting, working, last reply, never ran, registry-only bot, conversation with finished, unshared and running jobs, loading and failed reads); `test_coworker_page_guidance_mutations.py` reverts each rule and requires it to fail.
