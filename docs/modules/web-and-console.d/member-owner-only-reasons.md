- **Owns:** `owner-only.js` holds the one owner-only line and the copy for each place a member loses a control: connected apps, Admin, project settings, models, the workspace bot switch, card priority and a card waiting for release. Settings, project settings, the card panel, Admin and the release block call it; the line is screen copy only.
- **Promises:** A member sees "Only the workspace owner can change this." (or the matching sentence with who to ask) where an owner-only control would sit, and an owner sees no such line. A refused Settings section shows the reason instead of "Could not load … Owner access required". The Tool policy and Scheduled prompts sections no longer vanish or empty out for a member. The line names no counts, people, creators or trust levels, and says Coworker or workspace owner, never orchestrator. Server checks are unchanged; the controls that stay absent for a member are listed in `docs/invites.md`.
- **How it fails:** The reason only replaces a 403 for a viewer who is not an owner; an owner who gets a 403 or any other error keeps the error text.
- **Tests:** `tests/member_owner_only_reasons.mjs` (run by `tests/test_member_owner_only_reasons.py`) renders each place for a member and an owner; the same Python file proves the server still refuses a member for connections, trust, bot management and models.
