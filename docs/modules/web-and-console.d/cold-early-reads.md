- **Owns:** How the production document starts a route's first loads in `commonplace/web/assets.py`, `commonplace/web/__init__.py` and `commonplace/web/static/api.js`: an inline script that runs before the stylesheet, and gzip transfer encoding for text assets.
- **Promises:** The script, covered by a CSP hash like the other two inline scripts, starts the route's bundle and its first plain reads (identity, the board directory and, on a board route, that project's cards) beside the stylesheet instead of after it. The client takes each such read once, for the matching GET only, within 15 seconds; every write, every later read and every stale or failed early read goes to the network as before. Text assets of 1 KB or more are served gzip-encoded when the browser asks, with their own validator, `Vary: Accept-Encoding` and the same immutable caching; decoded bytes are identical.
- **How it fails:** An early read that fails, is refused or is stale is dropped and the normal read runs, so identity outages, sign-in (401) and permission errors behave as before. A bare `#/board` that guesses the wrong saved project makes one extra unused read. A browser without gzip, or with `gzip;q=0`, receives plain bytes. A read taken early is a fresh response, not a stored value, and never authorizes a write.
- **Tests:** `tests/test_early_reads.py` (script position and CSP hash, reads per route, one-shot taking, gzip bytes and validators) with `tests/early_reads_harness.mjs`; `tests/cold_bundle_browser.py` measures the cold board.
