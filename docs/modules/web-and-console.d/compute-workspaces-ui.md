- **Owns:**

  - `commonplace/web/static/compute-workspaces.js` and its section in `compute.js`/`compute.css`: the "Cloud workspaces" section of the Compute management screen, shared by Classic and the Deck Management tab. It lists records (name as a heading, one plain status, one resource line, the image, buttons named per workspace), shows a form (name, image choice or own address with help, preset sizes, CPU cores, memory in GiB, storage each with a "What do I need?" line, network, machine) with a resource preview, inline validation (red edge, icon and message) and a summary that links to the fields in error, a review step before confirm, an edit form that sends only changed fields with the version it opened at and recovers from a stale edit ("Reload and start over"), a details view and a danger-styled discard confirmation with Keep focused. Members see the list and details read-only. Cloud workspaces are one entry for every member: the Deck bar ("Compute"), the Classic sidebar and phone tab bar ("Cloud workspaces", first level) and the Classic account menu and palette (`rail.js`, `palette.js`, `app.js`).
- **Promises:**

  - Every state says what it is: loading, empty (owner and member, hidden while a form is open), failed load with a reload button, image list unavailable (creation disabled with the reason), each status with its sentence, and "Not started yet" until the lifecycle exists. No copy promises running or enforcement (one sentence per not-started and started state is reused everywhere); a saved record says "Saved in Commonplace. Nothing has been sent to a machine yet." Nothing is sent before the confirm step; a retry after a lost answer reuses the request id. Errors from the server land beside their field. All user text is escaped; there are no inline styles; on the phone (699px, Classic and Deck) targets are at least 44px, inputs 16px and hints 14px, the form scrolls by touch (in Deck `#content` stays the scroller), the actions are one 44px sticky row on the tab bar and fields and errors scroll clear of it, and the page never scrolls sideways at 390px; focus moves to the panel heading on open, to the first invalid field (or the summary for a form-level problem), to the confirmation line after a save, stays on the button while saving (`aria-busy` and a status line) and goes back to the opening button on close or Escape (Escape asks before typed values are lost); form controls use the `--control-line` token (3:1 in Deck) and the global `--line-strong` is unchanged.
- **How it fails:**

  - A failed or unanswered save keeps the person's values and says whether anything is confirmed; a form opened before the list changed (a rename included) says so at once, shows what was typed, disables its submit and offers to reload and start over; a 401 ends the visit like the rest of Compute; a 403 for the owner inventory still shows the read-only list.
- **Tests:** `tests/compute_workspaces_ui.mjs` (via `tests/test_compute_workspaces_ui.py`) and `tests/test_compute_workspaces_browser.py` (Classic and Deck, desktop and phone, owner and member).
