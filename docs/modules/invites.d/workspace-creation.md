- **Owns:** Browser workspace creation, its session-bound csrf proof and durable workspace_creations request ledger.
- **Promises:** POST /api/workspaces accepts only a person session with explicit same-origin Origin and the session's csrf value from GET /api/workspaces. All bearer credentials and service accounts are refused.
  Provisioning reuses ControlDB.create_workspace, assign_signup_plan and the signup default-board initializer. The new directory, owner membership and empty Commonplace board contain no copied data or members. Confirmation opens the new workspace's Home in both looks.
  The default owned-workspace cap is 5, configurable with COMMONPLACE_WORKSPACE_LIMIT. The existing plan hook separately enforces the free allowance. COMMONPLACE_WORKSPACE_CREATIONS_PER_HOUR defaults to 3 per person; COMMONPLACE_WORKSPACE_CREATIONS_PER_DAY defaults to 20 per instance. Both use the shared limiter and durable rolling counts. Replaying a person's request_id returns the same workspace without spending another allowance.
- **How it fails:** Validation, closed signup, caps, plans and rate limits return plain errors. Disk-low, backup pause and maintenance refusals are retryable and create no workspace. A completed control transaction retains an initialization marker until its empty default board is usable; a retry completes that workspace. Audit rows contain ids, time and decision, never the submitted name.
- **Tests:** tests/test_workspace_creation.py and tests/test_workspace_creation_safety.py exercise authority, csrf, caps, limits, slugs, provisioning, plan rollback, instance visibility, real memory search and isolation. tests/workspace_creation.mjs and tests/test_workspace_creation_ui.py cover confirmation, duplicate clicks, retries, csrf submission, refusals and automatic switching. tests/test_workspace_creation_browser.py covers both looks at 1280 and 390 pixels with captures.
