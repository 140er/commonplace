- **Owns:** `ThreadStore.append_rows` and `iter_messages` (also on `ThreadStoreV2`), the streamed `canonical_sha256`, and `continuity._archive`/`_write`: how a push onto a saved thread reads and extends it.
- **Promises:** Extending a thread needs memory in proportion to its archived bytes, not to a multiple of its parsed messages. The thread digest is hashed one message, and one megabyte of text, at a time and is byte-for-byte the digest that was always stored. `append` compares a longer transcript against the digest on the thread row instead of reading the saved rows back; `append_rows` takes only the new rows. `_archive` pages the saved messages and keeps only the archive segments, and `stream_push` reads each archive once.
- **How it fails:** `append_rows` refuses rows whose `seq` does not continue the saved count (`ValueError`). A thread whose row digest was not written by this code would now answer `ThreadConflict` to an `append`, as `ThreadStoreV2.append` already did. The first upload of a whole large transcript still holds its text several times (request body, parsed text, archive).
- **Tests:** `tests/test_long_thread_push_memory.py` bounds the allocation peak of a push onto an 8 MiB thread (about 15 times the thread before, about 3 after), proves the streamed digest equals the whole-thread digest, and compares `append_rows` with `append` on both stores.
