- **Owns:** `tests/test_gateway_memtrace.py` and `tests/test_gateway_memory_growth.py` exercise gateway allocation diagnostics, polling growth and native arena bounds; the Admin instance tests pin the new counters.
- **Promises:** Tests use synthetic local data and a stub memory worker. The polling test warms imports and selected workspace stores before comparing equal 600-request batches with unique queries, checking Python allocations, SQLite connections, descriptors, sockets, tasks and threads.
- **How it fails:** Growth limits allow a bounded number of transient background report connections and descriptors. Synthetic plateau checks cannot establish a production memory slope or reproduce the cost of a real memory worker. A one-time lazy allocation can land inside the measured batch under load; when the first batch exceeds the limit one more batch decides, because retained growth repeats and a one-off does not.
- **Tests:** The diagnostic unit tests verify off-by-default behavior, five-frame startup, ten-minute cadence, privacy, at most ten positive sites, snapshot rotation and cleanup, existing-tracer ownership and failure recovery. The native growth regression sends concurrent transcript uploads through the gateway using the shipped image environment, and asserts at most two live glibc arenas after each request batch. It fails with 31 arenas under the original image setting and skips where glibc statistics are unavailable. The Admin counter assertion fails against the original memory view because its new fields are missing.
