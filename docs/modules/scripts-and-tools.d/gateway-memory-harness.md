- **Owns:** `scripts/gateway_memory_harness.py` starts a temporary gateway and a separate stub worker, drives synthetic Deck and MCP requests, and writes optional JSON evidence.
- **Promises:** The harness measures process anonymous and resident memory, traced allocations, GC types, Python and native thread counts, descriptors, SQLite connections, sockets and asyncio tasks. The gateway child uses the shipped image's allocator default unless an explicit experiment overrides it. Route passes separate initialization from repeat traffic; a soak compares snapshots after an explicit warm-up baseline. Its data and admin socket directories are private and removed when the rig exits.
- **How it fails:** Models and external services are not exercised. Socket requests and process shutdown have deadlines; the caller must also apply a finite timeout to the overall experiment. Native allocator retention, page caches and tracing overhead can grow anonymous memory without increasing the live Python heap.
- **Tests:** `tests/test_gateway_memory_growth.py` uses the harness for bounded repeated polling. Manual route and soak results are described in `docs/system/gateway-memory-investigation.md`.
