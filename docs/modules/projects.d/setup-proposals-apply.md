- **Owns:** The owner's decision on a setup proposal (card #675 slice 2): `setups.apply`, `setups.reject`, `is_signed_in_owner`, and `POST /api/setup-proposals/<id>/apply` and `.../reject` with `{sha256}`.
- **Promises:** Only the signed-in owner in a web session decides; the owner's own agent token gets 403 `owner_only`, and members, their agents and other workspaces get the 404 of an unknown route. The digest check and the move out of `proposed` are one statement, so a proposal is decided at most once and a changed or stale version never applies. Apply runs every item as that owner through the existing services: the Coworker bot store without a connection, a project-bound Coworker conversation, and `models.catalog_add`, `models.put` and `models.put_workspace`. It grants no scope or chat consent, links no account and stores no credential. Each item's result (`ok` with the created id, or `error`) is stored as soon as it is known; the proposal ends `applied` or `partial`, is audited as `setup.apply` (with the digest and created ids) or `setup.reject`, and the proposer and owner read it back through `setup_show` and the routes.
- **How it fails:** A malformed digest is `sha256_invalid` (400), another version's digest is `sha256_mismatch` (409) and a decided proposal is `not_proposed` (409); none of them change anything. An item that fails (a project archived since proposing, a model the services refuse) is reported with its code and never stops the next item.
- **Tests:** `tests/test_setup_apply.py`, `tests/test_setup_proposals.py`.
