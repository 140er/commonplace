- **Owns:** `orchestration.resolve` (the one effective agent limit), `accepted_limit`, `runner_read` and the `Limit` record; `limits.check` reads it when the workspace switch is off; the project view carries `effective_limit` (configured, config, config_version, config_applies, effective, source).
- **Promises:** The effective limit is the smaller of the project limit and the accepted Coworker config's limit (the config binds only with a `[runner]` section), else the default of 3 with the workspace switch on, else no limit. Starts, claims, Admin and project settings read the same record, so a claim with the switch off is now refused at the accepted config's limit as a start already was; nothing is loosened. Project settings shows the project limit, the config's number and the one in effect in plain words.
- **How it fails:** A config without `[runner]` is shown with its number but marked not used and does not bind. An unreadable runner store reads as no accepted config.
