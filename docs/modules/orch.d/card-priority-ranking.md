- **Owns:** Priority-ordered starts in the trigger sweep and the Coworker's ranking list in the checkpoint (`commonplace/orch/triggers.py`, `durable.rankable_cards`).
- **Promises:** Within one sweep batch the todo events start most urgent card first, then event order, so a scarce agent slot goes to the most urgent card; due start retries are ordered the same way. The sweep cursor only moves past an event once every lower event of the batch is handled, so no card is skipped or started twice. A card blocked by another open card is refused as before and takes no slot. The checkpoint's `rankable` lists the todo and backlog cards no person ranked (priority, source, most urgent first); a person-ranked card is never listed. The Coworker role ranks them at start and when new cards arrive, with a reason per card. Only a disagreement that really matters goes to the owner: a person-ranked card that is `low` while it blocks an `urgent` or `high` card, raised as one question and never as a priority change.
- **How it fails:** A refused start (agent limit, block) records its miss and keeps its retry as before; the batch holds at most 50 events, so ordering applies inside a batch. A sweep that loses its cursor stops without writing, and the next sweep redoes the unhandled events.
- **Tests:** `tests/test_card_priority_ranking.py` (red on the base: priority-ordered starts and retries) with `tests/test_orch_start_retry.py` and `tests/test_orch_trigger_stall.py` for the unchanged retry and cursor behavior.
