- **Owns:**

  - `chat/coworkers/taxonomy.py` projects rail metadata from readable coworker conversations. `GET /api/coworkers/bots` retains every persona field and adds `section`, `private`, `unread`, `state`, `summary`, `coworker_count` and `coworkers`. `GET /api/coworkers/conversations` adds the same metadata to the caller's existing conversation rows. The original bootstrap and creation responses stay compatible.
  - A persona's `section` is null by default (display as "Bots"). A workspace owner can `POST /api/coworkers/bots/<id>/section` with exactly `{"section":"Core Ops"}` or `{"section":null}` to clear it. Names use `sanitize_name`, with a 60-character limit. Changes are audited by bot identifier and set/clear operation; section text never enters the audit log.
  - `team_bots`, a separate additive array on `GET /api/coworkers/bots`, uses the existing `BotStore.roster` authority and its existing owner/member private-thread unread counts. It contains `id`, `name`, `mine`, `shared`, `thread`, `section`, `private`, `unread`, `state` and `summary`. The registries are never joined by name or copied between databases. Team bots have no existing folder field, so their section remains null and this route cannot configure them.
- **Promises:**

  - States are the closed set `idle`, `working`, `waiting`, `live`. A latest coworker front job maps pending/running to working, needs-configuration/uncertain to waiting, done to live, and other outcomes to idle. A team bot uses the reader's own pending confirmation, running turn, or latest received message, in that priority order; absent facts mean idle. These are observations of stored front activity, not claims about external service health or canonical task completion.
  - A coworker entry identifies the latest response job per readable conversation and bot, with a state word as its summary. Bot summaries say "Needs you" when waiting, otherwise "0 coworkers", "1 coworker", etc. Waiting takes precedence over working, live and idle. Counts exclude all private conversations of other people, even for workspace owners. A group with several bots attributes its readable unread messages to each participating bot. A conversation inherits a section only when it has one bot.
  - Legacy personas are workspace-visible and have `private:false`. Team locks use the existing shared flag (`private` is its inverse). Conversation `private` denotes a DM. Inaccessible connection bindings suppress the persona and conversations containing it. Person sessions and the existing same-origin JSON write boundary remain mandatory; an agent or machine bearer cannot read or configure this projection.
  - Two bounded coworker queries include one batched audience/unread/latest-job lookup, independent of bot count. Connection authority uses a batched control lookup with existing authentication checks. Team projection reuses one roster call and one pending-confirmation lookup, never a per-bot thread scan. All limits use the existing directory caps.
  - The connection-authority helper holds the shared control lock through execution and row fetching. Section mutations fail closed without server authority, so standalone stores cannot bypass the required audit. `open_bots` returns the existing per-workspace cached store; requests retain that shared handle on success and failure rather than closing another caller's connection.
- **Tests:** `tests/test_coworker_taxonomy.py` covers additive contracts, owner-only sanitized sections, identifiers-only audits, the closed state set, paginated read cursors, private-thread/other-workspace/token isolation, share revocation, legacy upgrades and constant lookup counts with fifty bots. Regression probes require the control lock during both execute and fetch, refuse unaudited standalone set/clear operations, trace the actual cached route connection with a nonzero read count, and verify owner cleanup of that handle after successful and exceptional requests.
