- **Owns:**

  - `commonplace/chat/coworkers/owns.py` projects live board-card path contracts and runner admission holds into the conversation list and detail. Store reads opt in with `owns=True`; ordinary internal receipts and conversation bindings keep their existing shape.
- **Promises:**

  - `GET /api/coworkers`, `GET /api/coworkers/conversations`, and `GET /api/coworkers/conversations/{id}` add `owns` to each returned conversation. The field is an object with non-null `availability: "available" | "unavailable"`, `paths: array`, and `truncated: boolean`. Each path entry has non-null repo-relative `path: string`, nullable `locked: boolean`, nullable `shared_lock: boolean`, and nullable `lock_owner: string`. Paths include globs and sort lexically. Existing fields and mutation receipts are unchanged.
  - Example: `{"owns":{"availability":"available","paths":[{"path":"src/api/**","locked":true,"shared_lock":true,"lock_owner":"parser-worker"}],"truncated":false}}`. A board-less conversation returns an available empty list. An unreadable, archived or unavailable project returns an unavailable empty list, with no omission count or lock facts.
  - Ownership comes from the conversation's currently valid bound connections' assigned cards, or canonical chat-task origins belonging to that exact conversation. The board-card `paths` column is the current path-contract source; no separate step-contract table is invented. Group members receive the same projection as detail when they can read that board. Connection binding grants no execution authority.
  - A lock follows the existing admission rules: a doing card assigned to a connection, or a queued, leased, starting, uncertain or started runner job. Started jobs keep holding until their contract is cleared, including after a run-end receipt. A person's doing assignment alone does not hold. `locked` reports any overlapping holder; `shared_lock` reports another card's hold or multiple holders. `lock_owner` names the first other holder, otherwise the first own holder, in card order. The doing assignee takes precedence over the runner ledger's recorded worker; absent, expired, revoked or oversized names remain null. Names never fall back to connection, machine or thread identifiers.
  - Reads first enforce current workspace/person and conversation membership, then current board read policy. Only readable boards enter either contract or lock queries; project names alone grant nothing. A fresh person/board check fences publication. No canonical path or lock is persisted in chat, returned to token-authenticated callers, or fetched from a different workspace. Authorization and public-surface pins stay unchanged.
- **How it fails:**

  - Each conversation returns at most 200 unique paths. More paths, omitted unsafe/oversized legacy contracts, or more than 201 source jobs/cards set `truncated:true`. Canonical normalization rejects absolute, drive-relative, home-relative and escaping paths, and credentials are omitted whole. Source contract fields are capped at 32 KiB before transfer from SQLite. Contracts are not expanded against the filesystem.
  - Source reads use fixed batched queries rather than queries per conversation or path. Holder candidates are capped at 201 per board and overlap comparisons share the existing bounded contract-work budget. An unreadable runner store, an incomplete holder selection, or exhausted comparison budget yields null lock booleans and owner for affected paths; declared ownership can remain available. A missing runner store has no runner holds. Source stores are opened read-only without migrations, sweeps, launches or network calls.
- **Tests:**

  - `tests/test_coworker_owns.py` covers live detail/list refresh, shared display-name holds, all admission job states, canonical origin isolation, member/board/workspace/token isolation, unsafe legacy paths, response caps and fixed read-only source query counts. Existing coworker API/store tests guard authority and receipt compatibility.
