- **Owns:** `consent.py` stores one owner-private consent record per canonical runner machine in the control database. `routes.py` serves `GET` and `POST /api/compute/consent/<machine_id>` under the existing authenticated Compute prefix.
- **Promises:** Installation seeds denied revision-zero records without changing existing consent or revisions. Reads never grant. Every explicit Allow or Revoke requires an integer `expected_revision`; the transaction rechecks the person session, enrolling owner, workspace, machine and both live runner connections before a conditional update. A stale request receives HTTP 409 with the authorized current state and must wait for a new explicit decision. Relevant machine, connection, membership and account authority changes revoke and advance the same revision atomically.
- **Tests:** `tests/test_compute_consent_revision.py` drives real HTTP servers and SQLite, including two independent database connections, stale writes, authority loss, migration, failed-write rollback and account lifecycle. This core does not implement or verify Activity navigation, stopping or remounting.
