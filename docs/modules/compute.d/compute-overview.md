- **Owns:**

  - The Compute overview (`overview.py`, `overview_routes.py`, `workspace_lifecycle.py`; design `docs/system/compute-overview.md`): one read of every target machine, runner machine and cloud workspace with a status in plain words, health (the age of the last signal, what blocks a Coworker from starting there), usage (run counts, the latest resource report with its age, spend per currency, configured limits), recent activity and per-item owner actions. `GET /api/compute/overview`, `/overview/<kind>/<id>`, `/overview/<kind>/<id>/preview/<action>` and `POST /api/compute/overview/<kind>/<id>/<action>` (`routes.py` hands the path over; members may read).
  - The cloud workspace lifecycle: the table `cloud_workspace_lifecycle` (created by `workspace_lifecycle.schema` when the Compute store opens, cascading away with a discarded record) holds the phase (`not_started`, `starting`, `running`, `stopping`, `stopped`, `failed`), the pending request (`start`, `stop`, `restart`), a `seq` counter, the last executor report time and the last `request_id`. The owner's calls only record a request (`workspace_lifecycle.request`); `claim` and `report` are the executor seam, never reachable over REST, and `executor_available` is false until something registers on the gateway. `workspaces.has_started` also counts any phase but `not_started`.
- **Promises:**

  - A status never says running, starting or online without a fresh report: a reported phase is trusted for 600 s, a runner for the topology thresholds (180 s online, 900 s offline), anything older is `unknown` or `offline` with the age; a usage value nobody reported is `{known: false, reason}`, never zero; unknown spend is counted next to the total. Nothing in the overview opens a connection to a machine, reads custody or probes.
  - A start, stop or restart is a request until a machine reports; the app says "requested" and that this version cannot start workspaces on a machine. Stale (`expected_seq` and `expected_version`) and reused request ids are conflicts that change nothing; a repeat returns the same request. Members read cloud workspaces only, with no machine name, id or address and no runner label or spend; every write is owner-only, checked before the body is read, with a reason on every refusal. Every owner action is audited.
- **How it fails:**

  - `409 conflict` with `stale_state`, `request_pending`, `request_reused`, `already_running`, `already_starting`, `still_stopping`, `already_stopped`, `already_stopping`, `not_started`, `not_running`, `no_machine`, `needs_credential`, `revoked`, `nothing_to_withdraw` or `already_picked_up`; `400 invalid_request` naming `expected_seq`, `expected_version` or `request_id`; `403 owner_required` / `member`; `404 not_found` (`record` or `route`). An executor report for a stale claim or a move the state machine does not allow raises `StoreError` (`stale_claim`, `invalid_report`) and changes nothing.
