- **Owns:**

  - Cloud workspace records (`workspaces.py`, table `cloud_workspaces` in `compute.sqlite3`, `control.py` `_SCHEMA`, plus the columns `workspaces.schema` adds on open): a name and its NFC case-folded `name_key`, an image reference (curated or the person's own), CPU millicores, memory MiB, storage GiB, a network policy, an optional enrolled machine, a settings revision, the revision the machine last applied and an optional `request_id` with the hash of the values it created. Explicit literal SQL per statement; the table is not an authority table of the execution fence. `Store.list_workspaces`, `get_workspace`, `create_workspace` (returns `(item, created)`), `update_workspace`, `discard_workspace`, `bind_workspace_credential` (always refused), and `GET`/`POST /api/compute/workspaces`, `/workspaces/images`, `/workspaces/<id>`, `/workspaces/<id>/discard`, `/workspaces/<id>/credential` (`routes.py`). `Store._set_workspace_state` is the seam the later start/stop code writes `ready`, `failed` and `applied_revision` through; no REST path reaches it. Design: `docs/system/compute-workspaces.md`.
- **Promises:**

  - Image references are validated against the container reference grammar before anything is stored (no whitespace, quotes, shell characters, URL scheme, user info or leading dash; registries on local or private networks, IP addresses and a registry without a path are refused); limits have fixed ranges and steps (CPU 0.5 to 32 in 0.5 steps, memory 512 to 131072 MiB in 128 steps, storage 1 to 2048 GiB); names are NFC, 1 to 60 code points, visible, with a letter or digit, and unique by case-folded key; unknown and server-owned fields (`state`, `applied_revision`, `id`, any password or secret field) are refused. No secret and no registry login reference is accepted, stored or returned: private registries are refused until registry logins have their own custody purpose, and the credential route writes nothing.
  - Status is derived and never blank: `no_machine`, `needs_credential` (old records only), `pending` (not started), `restart_needed` (a started workspace whose saved settings moved on), `ready` (applied revision is current), `failed` with a reason from a closed set. Nothing in this slice starts a container, so a record is `pending` and not started. The creation cap equals the list limit (100). A repeated `request_id` with the same values returns the earlier record; with different values it is a conflict.
  - Any current member of the workspace may read the list, one record and the image options (members never get a machine name or id or a registry reference); every write and every other Compute route stay owner-only (`owner_required`, checked before the body is read), and a personal access token is never accepted for these routes. A stale `expected_revision` on edit is a conflict that changes nothing. A never-started record can be discarded; a started one cannot.
- **How it fails:**

  - Every refusal carries a `reason` and, for a form field, the `field`: `invalid_request` for a refused value (for example `image` / `registry_private`, `cpu_cores` / `range`, `name` / `no_letter`, or `unknown_field`, `required`, `no_changes`, `body` without a field); a taken name, a stale revision, a reused request id, the cap, a started workspace or an unavailable registry login is `conflict` (409) with its reason; an unknown machine is `not_found` (404); a started workspace cannot move to another machine (`conflict`, `machine_locked`); a non-owner write is `owner_required` (403); a foreign record is `not_found`. The full list is in `docs/system/compute-workspaces.md`.
