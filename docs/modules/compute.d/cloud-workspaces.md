- **Owns:**

  - Cloud workspace records (`workspaces.py`, table `cloud_workspaces` in `compute.sqlite3`, `control.py` `_SCHEMA`): a name, an image reference (curated or the person's own), CPU millicores, memory MiB, storage GiB, a network policy, an optional enrolled machine, an optional registry credential reference, a settings revision and the revision the machine last applied. Explicit literal SQL per statement; the table is not an authority table of the execution fence. `Store.list_workspaces`, `get_workspace`, `create_workspace`, `update_workspace`, `bind_workspace_credential`, and `GET`/`POST /api/compute/workspaces`, `/workspaces/images`, `/workspaces/<id>`, `/workspaces/<id>/credential` (`routes.py`). `Store._set_workspace_state` is the seam the later start/stop code writes `ready`, `failed` and `applied_revision` through; no REST path reaches it. Design: `docs/system/compute-workspaces.md`.
- **Promises:**

  - Image references are validated against the container reference grammar before anything is stored (no whitespace, quotes, shell characters, URL scheme, user info or leading dash); limits have fixed ranges and steps (CPU 0.5 to 32 in 0.5 steps, memory 512 to 131072 MiB in 128 steps, storage 1 to 2048 GiB); names are unique ignoring case; unknown and server-owned fields (`state`, `applied_revision`, `id`, any password or secret field) are refused. A private-registry record holds only a credential reference, bound once; changing the image's registry or clearing the private flag drops it. No secret is accepted, stored or returned.
  - Status is derived and never blank: `no_machine`, `needs_credential`, `pending` (not started), `ready`, `failed` with a reason from a closed set. Nothing in this slice starts a container, so a record is `pending` and not started; `restart_needed` is true only when a started workspace has an older applied revision than its settings revision.
  - Any current member of the workspace may read the list, one record and the image options (members get no registry reference); every write and every other Compute route stay owner-only (`owner_required`). A stale `expected_revision` on edit is a conflict that changes nothing.
- **How it fails:**

  - A refused value is `invalid_request` with the `field` and a fixed `reason` code (for example `image` / `characters`, `cpu_cores` / `range`); a taken name or stale revision is `conflict` (409) with its reason; an unknown machine is `not_found` (404); a started workspace cannot move to another machine (`conflict`, `machine_locked`); a non-owner write is `owner_required` (403); a foreign record is `not_found`.
- **Tests:** `tests/test_compute_workspaces.py` (API: create, edit, image injection attempts, limit ranges, status, owner-only, member read-only, concealment, audit).
