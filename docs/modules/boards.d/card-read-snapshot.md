- **Promises:** Opening a card (`GET /api/cards/<n>`, `task_show`) does not queue behind the board's writers. When no claim on its board has lapsed and no snooze is due, the card is read on a read-only snapshot (`_show_snapshot`) instead of the write transaction, so a long board write (a project list refresh, a start) no longer holds the card panel waiting. The card it returns is the same one the write path returns (`_shown` builds both).
- **How it fails:** If a lapsed claim or a due snooze exists, or the snapshot would have to write, the read falls back to the write transaction, which expires or wakes first, exactly as before. A missing or hidden card refuses with the same error on either path.
- **Tests:** `tests/test_card_show_read_snapshot.py` holds a board write open and checks the card read answers while it is held (red on the write-locked read), and that a lapsed claim is still expired by the read.
