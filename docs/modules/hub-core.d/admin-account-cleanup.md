- **Owns:** Transactional membership removal and disposable-user deletion in `ControlDB`.
- **Promises:** Active instance-admin authority, explicit disposable marking, owner and membership guards, workspace-scoped credential deletion and append-only audit insertion share the cleanup transaction; literal SQL names only the supported control tables; workspace content and historical attribution remain intact.
- **How it fails:** Last owners, unmarked real accounts, remaining memberships, last administrators and unsupported foreign-key dependencies are refused; any cleanup or audit failure rolls back all removals.
- **Tests:** `tests/test_admin_account_cleanup.py` covers scoped credentials, legacy migration, authorization, eligibility, foreign keys, crash rollback, idempotence, unchanged prior audit rows, rejected content-table plans and retained thread-store rows; the A4 evaluation guard remains unchanged.
