- **Owns:** What each connection trust level allows in plain words (`trust_levels.py`, one source for the Admin projection and its refusal texts) and the owner's change of one connection's level (`ControlDB.set_connection_trust`, `PATCH /api/connections/<id>` with `{"trust": ...}`).
- **Promises:** Only the signed-in workspace owner moves an active personal access token between `untrusted` and `standard`; the new level goes through `Policy.build`, so a lowering the policy would refuse at creation (an untrusted writer needs a `write_wing`) is refused with the same reason. `trusted` is never granted there, a connection that holds it, runner and project bot connections, OAuth clients and revoked or expired connections are left alone with a stated reason, and members and agent tokens get 403. Each change appends one `connection.trust` audit row (`<before> -> <after>`). The Admin connections section returns `trust_levels`, and per connection `trust_summary` and `trust_change` (`can_change`, `options`, `reason`); the page renders what the server sends and asks for a confirm before the write. The project bot start-permission form shows its blocker and a link to add a machine when none is registered.
- **How it fails:** A refused change answers 409 with an owner-safe message and leaves the stored policy as it was; an unknown level or an extra field answers 400.
- **Tests:** `tests/test_connection_trust_level.py` (server path, refusals, audit), the `trust` case of `tests/admin_runtime_ui.mjs` via `tests/test_admin_runtime_ui.py`, and `tests/test_trust_form_blocker.py`.
