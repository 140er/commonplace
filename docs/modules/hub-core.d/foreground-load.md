- **Owns:** `commonplace/foreground_load.py` keeps people's worker calls ahead of the search-index backfill. `WorkerClient.post` wraps every call from a person in `request()`, which never waits, and sends the backfill's `internal/write_mirror_units` through `background_call`, which waits (at most 5 s) until no person's call runs and none ended in the last 0.25 s, runs the write, then rests for `COMMONPLACE_SEARCH_INDEX_REST_RATIO` (default 2, `0` turns it off, capped at 5 s) times the write's own run time.
- **Promises:** A person's request is never delayed by the gate; only the backfill waits. A busy workspace still indexes slowly, because the wait is bounded. The index job's own helper calls do not count as people (`background()`).
- **How it fails:** A backfill write that fails still rests, so a refusing worker is not hit in a tight loop. The gate lives in one process; a second gateway process does not see the first one's requests.
- **Tests:** `tests/test_search_index_contention.py` runs the real sweep and worker client against a synthetic one-CPU worker and checks that search latency stays near its idle value, that no index write starts inside a search, and that rest follows write cost.
