- **Owns:** Three guards on a gateway call to the memory worker. A call whose caller has less than `MIN_WORKER_WINDOW_S` (0.25 s) left on its deadline is not sent (`TimeoutError`): the startup context, whose whole budget is 80 ms, used to send a memory search the caller gave up on and the worker ran to the end. Once a request's worker call is answered busy (`-32001`), the request's later worker calls raise `WorkerBusy` without asking again (`MemoryWait.busy`). A worker call of a second or more logs `worker call took Ns: call=<tool>`, and a refused index write logs `worker refused an index write: code=… message=…` with the worker's own refusal (a preflight gate such as a diverged index or a read-only palace; never user content).
- **Promises:** A busy answer takes the request's wait budget at most (it took 13 to 15 s when each of a search's several calls waited out the worker's lock bound); abandoned startup searches no longer accumulate in the worker; the reason an index write was refused is in the log. Calls without a short deadline or a budget behave as before.
- **How it fails:** A call on a deadline under 0.25 s is refused even if the worker would have answered in time.
