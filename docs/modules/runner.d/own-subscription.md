- **Owns:** The Grok chat CLI on the runner (card #661): `SAFE_ARGV["grok"]` (tools off: `-p`, `--no-memory`, `--no-subagents`, `--disable-web-search`, `--max-turns 1`, an empty `--tools`; the listed approval and tool flags denied), Grok's headless JSON in `_unwrap`, `failure_code` with the codes `cli_signed_out`, `cli_not_entitled` and `cli_outdated`, and the hub's chat replies for them (`ACCOUNT_FAIL_CODES`). Connection lookups by machine and provider in the job and chat account fences.
- **Promises:** Only the verdict leaves the machine: the CLI's error output is matched locally and dropped. A failed run is never offered to another account or provider; the person gets the reason and the next step in the chat. Chat child processes keep the allowlisted environment, so the Grok CLI uses its account sign-in and never an API key.
- **How it fails:** A CLI whose words match none of the patterns reports `cli_failed` as before. A hub without these codes refuses the report (deploy the hub first).
